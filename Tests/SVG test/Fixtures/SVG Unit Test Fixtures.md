# SVG Stage 1 Normalization Unit Test Fixtures

## Overview

The Graphics32 SVG engine follows a two-stage architecture modeled on `linebender/resvg` / `usvg`:

1. **Stage 1 (`usvg`)**: XML parsing, CSS cascade evaluation, attribute inheritance, and AST normalization. Stage 1 simplifies raw SVG markup into an explicit, deterministic Abstract Syntax Tree (AST).
2. **Stage 2 (`resvg`)**: Rasterization of normalized AST nodes onto Graphics32 `TBitmap32` surfaces.

To ensure Stage 1 parsing and normalization correctness without the noise and overhead of image rendering, Graphics32 provides a **file-based text fixture test suite**.

---

## Test Fixture Format

Each test scenario is stored in a single `.test` file under `Tests/SVG test/Fixtures/`.

A fixture file consists of two sections separated by delimiter headers:

```
--- SVG ---
<svg width="200" height="100">
  <defs>
    <linearGradient id="g1">
      <stop offset="0" style="stop-color: rgb(50,50,50); stop-opacity: 1;"/>
    </linearGradient>
    <radialGradient id="r1" href="#g1" cx="10" cy="20" r="30" spreadMethod="reflect"/>
  </defs>
</svg>
--- EXPECTED AST ---
TSvgDocumentNode (width=200px, height=100px)
  TSvgDefsNode
    TSvgLinearGradientNode (id="g1") (spreadMethod=smPad, units=guObjectBoundingBox) (x1=0%, y1=0%, x2=100%, y2=0%)
      TSvgGradientStop (offset=0, color=#FF323232, opacity=1)
    TSvgRadialGradientNode (id="r1") (spreadMethod=smReflect, units=guObjectBoundingBox) (cx=10px, cy=20px, r=30px, fx=10px, fy=20px)
      TSvgGradientStop (offset=0, color=#FF323232, opacity=1)
```

### Section Breakdown:
- **`--- SVG ---`**: The raw input SVG markup to be parsed by `ParseSvgXml`.
- **`--- EXPECTED AST ---`**: The expected multi-line text tree output generated by calling `TSvgNode.DumpTree` on the parsed document root.

---

## AST Tree Dumper

The `TSvgNode.Dump` method produces a human-readable, deterministic text tree representing the normalized AST.

Key normalization properties formatted by `Dump` include:
- **Node Type & ID**: Class name and explicit element `id`.
- **Dimensions & Units**: Explicit lengths formatted with unit suffixes (e.g. `200px`, `50%`).
- **Default Resolution**: Unspecified `fx`/`fy` radial coordinates resolved to `cx`/`cy`.
- **Color Stops & Styles**: Stop colors resolved to 32-bit hex values (`#AARRGGBB`) and opacities.
- **Spread Methods & Transforms**: Gradient units (`userSpaceOnUse`, `objectBoundingBox`), `spreadMethod` enums, and non-identity matrix transformations.
- **Subtree Hierarchy**: Container groups, defs, cloned `<use>` subtrees, and shapes.

## DUnit Test Integration

Stage 1 fixture tests are integrated with DUnit via the file test framework in `Tests/DUnit/FileTestFramework.pas`:

```pascal
FileTestSuite := TFolderTestSuite.Create(
  'SVG Stage 1 Normalization',
  TSvgStage1FileTest,
  'Tests/SVG test/Fixtures',
  '*.test',
  True // Recursive directory traversal
);
RegisterTest(FileTestSuite);
```

During test execution:
1. `TFolderTestSuite` recursively scans `Tests/SVG test/Fixtures/` for all `*.test` files.
2. For each fixture file, a `TSvgStage1FileTest` instance is created.
3. The test parses the input SVG into a `TSvgDocumentNode`.
4. `actualDump := docNode.DumpTree` is generated and asserted against `expectedDump`.

## Adding and Updating Fixtures

1. **Adding a New Test Case**:
   - Create a new `.test` file under `Tests/SVG test/Fixtures/Stage1/<Category>/`.
   - Add the `--- SVG ---` markup and the `--- EXPECTED AST ---` block.

2. **Golden Update Mode**:
   - When AST schema or normalization rules evolve intentionally, pass the command line switch `-UPDATE_SVG_FIXTURES` when running the test suite to automatically update the `--- EXPECTED AST ---` section in all fixture files.

3. **Adding New Data Driven Test Cases**:
   - Create a new folder under `Tests/SVG test/Data/` and populate it with `.svg` test files.
   - Execute the `GenerateFixtures.ps1` PowerShell script to generate `.test` files corresponding to the `.svg` files in the `Data` folder.
   - Use `UPDATE_SVG_FIXTURES`, as described above, to update the test case fixtures.
